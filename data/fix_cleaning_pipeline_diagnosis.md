# Diagnosis: Fix Cleaning Pipeline to Reproduce Original Training Data

## Problem

Four train sets fail the `confirm_data_is_same.py` check (content differs, not just ordering):
- `es-en/train`, `fr-en/train`, `fr-oc/train`, `oc-en/train`

Test/val pass for all pairs. `an-en`, `es-an`, `fr-mfe`, `mfe-en` train sets all pass.

## Root Cause

The `data/data-cleaning-pipeline` submodule is currently at commit **`c33cd2f`** (April 23, 2025),
which added the soft hyphen character (U+00AD) to `config/all_whitespace.txt`.

This change alters cleaning behavior for pairs containing soft hyphens:
- **Before `c33cd2f`**: soft hyphens are rare → classified as invalid by `_statistical_character_set` → any pair containing a soft hyphen is **deleted** by `normalize_character_set`
- **After `c33cd2f`**: soft hyphens are treated as whitespace → normalized to a space first → these pairs **survive** cleaning (with the hyphen replaced by a space)

The original data for all 4 failing pairs was cleaned with a pipeline version **before** `c33cd2f`:
- **CCMatrix (es-en, fr-en)**: cleaned in the `LRRomance` project (a separate project with its own older pipeline checkout, ~May 2025)
- **NLLB (oc-en, fr-oc)**: cleaned in the original CharLOTTE research project, also with a pre-`c33cd2f` pipeline version (~Feb 2026)

### Evidence

- **NLLB oc-en**: same raw TMX (6,923,325 lines in both), but original deleted 194,464 pairs vs. new deletes only 194,374 (90 fewer). All diverging pairs attributed to `normalize_character_set`.
- **CCMatrix es-en**: diff of first 1M clean lines shows new has extra lines exactly where soft-hyphen pairs appear; pairs present in both differ by `compren­der` (soft hyphen U+00AD) in original vs. `compren der` (space) in new.
- `char_sets` files: same character inventory but different counts (new has more chars because the extra soft-hyphen pairs were kept).

The commit immediately before `c33cd2f` is **`349212d`** (June 17, 2024 — "Added allowed_characters list to Thai cleaning config").

## Fix

Pin the `data/data-cleaning-pipeline` submodule to `349212d`, then re-clean and rebuild.

### Step 1: Revert pipeline submodule

```bash
cd data/data-cleaning-pipeline
git checkout 349212d
cd ../..
```

Verify soft hyphen is gone:
```bash
grep -c "00AD" data/data-cleaning-pipeline/config/all_whitespace.txt
# Expected: 0
```

### Step 2: Re-clean the 4 affected datasets

Run from the repo root (requires `.env` to be set):

```bash
source .env
raw_data=${DATA_HOME}/data/raw
cd data/data-cleaning-pipeline

python pipeline.py -p 8 -d -v -s ${raw_data}/CCMatrix/es_en
python pipeline.py -p 8 -d -v -s ${raw_data}/CCMatrix/fr_en
python pipeline.py -p 8 -d -v -s ${raw_data}/nllb/oc_en
python pipeline.py -p 8 -d -v -s ${raw_data}/nllb/fr_oc

cd ../..
```

Then re-apply the 10M truncation for CCMatrix (as in `clean_data.sh`):

```bash
for f in ${raw_data}/CCMatrix/es_en/cleaned/src.txt \
          ${raw_data}/CCMatrix/es_en/cleaned/tgt.txt \
          ${raw_data}/CCMatrix/fr_en/cleaned/src.txt \
          ${raw_data}/CCMatrix/fr_en/cleaned/tgt.txt; do
    head -n 10000000 $f > $f.temp && mv $f.temp $f
done
```

### Step 3: Re-run make_training_data.sh

```bash
bash data/make_training_data.sh
```

### Step 4: Verify

```bash
python data/confirm_data_is_same.py
# Expected: all PASSED! (not just PASSED AFTER SORTED)
```

## After Confirming the Fix

Commit the submodule pointer change so anyone cloning the repo gets the correct pipeline version:

```bash
git add data/data-cleaning-pipeline
git commit -m "Pin data-cleaning-pipeline to 349212d (before soft-hyphen whitespace change)"
```
